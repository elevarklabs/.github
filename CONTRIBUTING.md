# Contributing to Elevark Labs projects

Thanks for your interest. These guidelines apply to every public Elevark Labs repository unless a repo has its own `CONTRIBUTING.md`.

## Before you start

- **Bugs:** search existing issues first. If yours is new, open an issue that includes reproduction steps, what you expected, and what actually happened.
- **Features:** open an issue to discuss the idea before writing code, so effort isn't wasted on something out of scope.
- **Security issues:** don't open a public issue. See [SECURITY.md](./SECURITY.md).

## Pull requests

1. Fork the repo and branch from `main` (`feat/…`, `fix/…`, `docs/…`).
2. Keep changes focused. One logical change per PR.
3. Add or update tests and docs alongside the code.
4. Make sure lint, type checks, and tests pass locally.
5. Write a clear PR description: what changed, why, and how you tested it.

We use [Conventional Commits](https://www.conventionalcommits.org/) for commit messages (`feat:`, `fix:`, `docs:`, `chore:` …).

## AI-assisted contributions

AI-assisted code is welcome. You're responsible for understanding, testing, and standing behind everything you submit.

## Conduct

Be respectful, constructive, and assume good intent. We may remove comments or contributions that are harassing or abusive.
